# Public Incident Fields

<p class="ad-lede">The public app shows citizens where emergencies are and what to do about them. It never shows how the control room responds. This page lists the only incident and warning fields that leave the private side, the rule for publishing an incident, and the message a private instance sends to publish it.</p>

<div class="ad-meta" markdown="1">
<span>**Based on:** [data model](../milestones/ms2-elaboration/data-model.md), [GDPR analysis](gdpr-compliance.md), [threat model](threat_model.md) (PT1, PT2, PT8)</span>
</div>

## When an incident is public { #rule }

An incident is public only when all of these are true:

1. An operator **validated** it.
2. An authorized private app **published** it. The incident records when and by whom.
3. Its status is not `closed`.

A public incident is never a copy of the private record. The private side builds a new record from an allow-list of fields, so a field that is not listed below cannot reach the public side, even by mistake. The public side rejects any record that carries an extra field.

## Public incident fields { #public-fields }

The private side sends the fields in the first table. Required fields are always present. Optional fields are sent only when the private side has them, and only for the incident types listed.

| Field               | Type                            | Required | Types                                         | Meaning                                                                                                                        |
| ------------------- | ------------------------------- | -------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `type`              | enum                            | yes      | all                                           | `forest_fire`, `urban_fire`, `road_accident`, `flood`, `medical`, `hazmat`, `search_rescue`.                                   |
| `severity`          | enum                            | yes      | all                                           | `critical`, `high`, `moderate`, `low`.                                                                                         |
| `status`            | enum                            | yes      | all                                           | `active`, `controlled`, `monitoring`. Closing an incident is the `end` action of the [publication message](#publish), not a status. |
| `location`          | GeoJSON Point                   | yes      | all                                           | Coordinates in WGS 84 (longitude, latitude), rounded to 3 decimal places (about 100 m). A line or an area is reduced to its centre. |
| `started_at`        | date and time with zone         | yes      | all                                           | When the incident started.                                                                                                     |
| `description`       | text                            | no       | all                                           | Written for citizens, in Portuguese. The internal description is never used.                                                   |
| `vehicles_on_scene` | integer                         | no       | `forest_fire`, `urban_fire`                   | A number only.                                                                                                                 |
| `current_area`      | GeoJSON Polygon or MultiPolygon | no       | `forest_fire`, `urban_fire`, `flood`, `hazmat` | The area affected now.                                                                                                         |
| `forecast_area`     | GeoJSON Polygon or MultiPolygon | no       | `forest_fire`, `urban_fire`, `flood`, `hazmat` | The projected area, shown as a forecast and never as a fact.                                                                   |

The public side adds these fields. The private side never sends them, and a publication that carries one of them is rejected:

| Field          | Type                    | How it is set                                                                                                         |
| -------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `id`           | integer                 | Generated by the public database. The internal code (`INC-0418`) and the private id are not public.                   |
| `updated_at`   | date and time with zone | When the public side last received the incident. Drives the "updated" label and the stale data warning.               |
| `municipality` | text, may be empty      | The municipality that contains `location`. Empty outside every zone.                                                  |
| `district`     | text, may be empty      | The district of that municipality.                                                                                    |

`updated_at` is the reception time, not a time sent by the private side, so a private instance with a wrong clock cannot make old data look recent. For the same reason it is never compared with `started_at`.

There is no place name field. Citizens see the municipality, computed from the coordinates, so every incident is named the same way.

## Public warning fields { #warning-fields }

A public warning is issued to citizens for an area, so issuing it is publishing it.

| Field         | Type                            | Required | Set by  | Meaning                                                       |
| ------------- | ------------------------------- | -------- | ------- | ------------------------------------------------------------- |
| `id`          | integer                         | yes      | public  | Generated by the public database.                             |
| `message`     | text                            | yes      | private | What citizens are told, in Portuguese.                        |
| `severity`    | enum                            | yes      | private | `critical`, `high`, `moderate`, `low`.                        |
| `area`        | GeoJSON Polygon or MultiPolygon | yes      | private | Where the warning applies.                                    |
| `issued_at`   | date and time with zone         | yes      | private | When it was issued.                                           |
| `last_update` | date and time with zone         | yes      | public  | When the public side last received the warning.               |
| `incident_id` | integer                         | no       | public  | The public incident it refers to. The private side names that incident by its `ref` (`incident_ref`, see [the publication message](#publish)); the link is set only when that incident is public and was published by the same instance. |

- A warning is active until the private side ends it (the `end` action). An ended warning leaves the public app.
- A warning does not need an incident. When an incident leaves the public app, the link on its warnings is cleared and the warnings stay.
- The operator who issued a warning is never public.

## Language { #language }

Ad Omnia is a Portuguese application. Every text shown to citizens (`description`, `message`) is written in Portuguese. Error codes returned by the API (such as `not_found`) are not shown to citizens; the public app shows its own Portuguese message for each one.

## Never public { #never-public }

| Data                                                            | Why                                                              |
| --------------------------------------------------------------- | ---------------------------------------------------------------- |
| Internal description and source-specific attributes             | May hold names, phone numbers, vehicle plates or radio details.  |
| The data sources behind an incident                             | Shows how the platform gets its information.                     |
| Operators: who created, validated, published or issued anything | Personal data.                                                   |
| Assets: callsigns, owner agency, positions, crew size           | Operational security, and it would show where resources are not. |
| Assignments, orders, acknowledgements, recommendations          | The response plan.                                               |
| Alerts, observations, incident relations, audit log             | Internal workflow.                                               |
| Prediction scores, confidence, model version                    | Statistics that citizens could misread as a decision.            |
| Incident end date                                               | Closed incidents are not public.                                 |
| Exact location                                                  | Public locations are rounded to about 100 m.                     |
| The `ref` of a published item and the instance that published it | They identify items between an instance and the public side only. |

Details about people involved in an incident (victims, callers, reporters) are not in the data model, and are never part of a public field.

## Publishing in the data model { #data-model }

Three columns on the incident record support publication.

| Column                         | Meaning                                                   |
| ------------------------------ | --------------------------------------------------------- |
| `is_public`                    | The incident is published.                                |
| `published_at`, `published_by` | When and by whom. Both are set together with `is_public`. |
| `public_description`           | The citizen text. Empty when there is none.               |

The database enforces the rules: an incident can only be published once it is validated, and `published_by` is set exactly when `published_at` is. Unpublishing clears all three, and the audit log keeps the history. Warnings need no extra column.

## The publication message { #publish }

Each private instance publishes by pushing a signed message to the public side's publish endpoint: `POST /api/ingest/incidents` or `POST /api/ingest/warnings`. The endpoint is a separate process from the read-only API, with its own database account. The full contract, including the signature, is in the `backend-public` README.

```json
{
  "action": "create",
  "ref": "3f2b8c1e-4d5a-4b6c-9e7f-0a1b2c3d4e5f",
  "version": 1,
  "data": {
    "type": "road_accident",
    "severity": "moderate",
    "status": "active",
    "location": { "type": "Point", "coordinates": [-8.654, 40.641] },
    "started_at": "2026-08-12T14:20:00+00:00"
  }
}
```

| Field     | Meaning |
| --------- | ------- |
| `action`  | `create`, `update` or `end`. `end` removes an incident from the public app, or ends a warning. |
| `ref`     | A random UUID (version 4, lowercase) that the private side generates once for each item it publishes and keeps with the item. It identifies the item between that instance and the public side, and is never shown to citizens. The private side never knows or sends public ids. |
| `version` | A positive integer that increases with every change to the item. |
| `data`    | The incident or warning, with only the fields the private side sends (tables above). Required for `create` and `update`, not allowed for `end`. A warning names its incident with `incident_ref`, that incident's `ref`. |

The public side applies these rules:

- **Signed by an active instance.** Each instance signs every message with its own key, and the public side stores only that instance's public key. A message that is not signed, now, by a registered and not revoked instance changes nothing.
- **Strict schema.** An unknown field, in the envelope or in `data`, or a missing required field, rejects the message.
- **Ownership.** An instance can only update or end the items it created.
- **Only newer versions.** A message whose version is not newer than the stored one changes nothing, so a repeated or old message is harmless. An ended item never comes back.
- **Publication log.** Every accepted message is recorded with its instance, action, version and time, together with the signed message itself, in a log that cannot be changed or deleted.

## The public schema { #schema }

The public side accepts and returns incidents and warnings only in the shape described above. Each model lists its fields and rejects anything else, so an internal field cannot be returned by accident. Responses always contain every field: a field without a value is `null`, so every response can be checked against the schema. Times are returned in UTC.

An incident with only its required fields:

```json
{
  "id": 2,
  "type": "road_accident",
  "severity": "moderate",
  "status": "active",
  "location": { "type": "Point", "coordinates": [-8.654, 40.641] },
  "started_at": "2026-08-12T14:20:00+00:00",
  "updated_at": "2026-08-12T14:20:00+00:00",
  "description": null,
  "vehicles_on_scene": null,
  "current_area": null,
  "forecast_area": null,
  "municipality": "Aveiro",
  "district": "Aveiro"
}
```

An incident with optional fields:

```json

  "status": "active",
```

## Public API { #api }

The read-only API serves the published state. It has no access to private data stores, and its database account can only read.

| Request                                                                  | Response                                                          |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| `GET /api/public/incidents?type=&severity=&status=&page=&limit=`         | `{"data": [incident, ...], "meta": {"page", "limit", "has_next"}}` |
| `GET /api/public/incidents/{id}`                                         | `{"data": incident}`                                              |
| `GET /api/public/warnings?page=&limit=`                                  | `{"data": [warning, ...], "meta": {"page", "limit", "has_next"}}`  |

- Lists are ordered by the last update, most recent first.
- `limit` is 1 to 100 (default 50) and `page` is 1 to 1000 (default 1).
- Filters accept only the enum values above. Unknown parameters and invalid values are rejected.
- Errors are a fixed code only: `400 {"error": "bad_request"}`, `404 {"error": "not_found"}`, `405 {"error": "method_not_allowed"}`, `500 {"error": "internal_error"}`.
